# Novel Graph Lab

**物語全体を読み、証拠をたどる。**

長編小説を再利用可能なナレッジグラフに変換し、質問に基づいて原文を検索し、3D アニメーションで証拠パスを再生します。

## まずはデモを見る

オンライン版はログインも API キーも不要で、元の研究デモ **739 ノード・1,886 エッジ・7 つの保存済み質問** を含みます。

- まず **92 個の孤立ノード（12.4%）** を含む完全な力学指向グラフを表示します。
- ドラッグで回転、ホイールで拡大縮小、ノードをクリックして証拠と関係を確認。
- 質問を選択して検索アニメーションを再生。一時停止・ステップ実行・速度変更・タイムラインのスクラブに対応。
- 既定では完全グラフ上で検索をハイライトし、質問サブグラフへの切り替えは明示的に選択した場合のみ。
- 光点は観測可能な検索・引用パスを表し、テキストは証拠の要約であり、モデル内部の私的な思考連鎖ではありません。

オンラインデモは履歴の再生のみで、API キーは受け付けません。新しい小説と実際の質問応答はローカルで実行してください。

## 3 ステップで開始

必要なのは **Python 3.10+** のみ。実行にサードパーティの Python パッケージ、Node、フロントエンド依存、CDN は一切不要です。

```bash
git clone https://github.com/fuxiaoji/novel-graph-lab.git
cd novel-graph-lab
python server.py --open
```

Windows では `start.cmd` をダブルクリックしても起動します。既定で [127.0.0.1:8765](http://127.0.0.1:8765) が開き、ポートが使用中の場合は `--port 8767` を指定できます。

1. 「インポート」をクリックし、TXT / Markdown を選択。UTF-8 と GB18030 に対応。
2. Chat Completions 互換の Base URL、モデル ID、API キーを入力。ローカルモデルはキーを空欄にできます。
3. 質問を入力し「検索して回答」をクリック。初回はチャンクごとにグラフを構築し、以降は再利用します。

API は `POST {base_url}/chat/completions` を使用し、`model`、`messages`、`max_tokens`、JSON 指示のサポートが必要です。モデル名はプロバイダ提供の実際の ID を入力し、各社独自の拡張パラメータは実装していません。リモート API は HTTPS、ローカルモデルは localhost の HTTP を利用できます。[API リファレンス](https://api-docs.deepseek.com/api/create-chat-completion/)

## グラフが質問応答をどう助けるか

**全文チャンク分割 → LLM 抽出 → 引用の逐語検証 → 完全グラフ → クエリ計画 → BM25 による位置特定 → 2 ラウンドの関係拡散 → 原文による補足検索 → 引用付き回答。**

人物、場所、時間、物体、出来事、証言、矛盾を保持します。原文を先に削除しないため、抽出で漏れた内容も原文補足検索で見つけられます。日本語・中国語はバイグラム分割、英語は単語単位でマッチングします。

新しいグラフでは、ノードとエッジの引用が対応チャンクに逐語的に存在しなければならず、関係には文字位置を保存します。名前は大文字小文字・空白のみ正規化し、別名は検索に使いますが、曖昧な同一人物は強制的に統合しません。回答に存在しない引用にはフラグが付きます。

## 指標の定義

| 指標 | 定義 |
| --- | --- |
| ノード数・エッジ数 | 完全グラフの総量。サブグラフ絞り込み後も変わりません |
| 孤立ノード率 | 他のノードに接続されていないノード数 / 総ノード数。自己ループは他ノードへの接続に含めません |
| 原文カバー率 | ノードの証拠が原文中で占める文字区間の和集合 / 原文の文字数。重複は 1 回のみカウント |
| 計算不可 | 完全な原文や位置がない場合。抜粋の長さを全文の長さとしてはなりません |

旧デモは完全な小説本文と座標が保存されていないため、カバー率は「計算不可」と表示されます。新しくインポートした小説では計算できます。引用カバー率は回答精度と同じではありません。

## 保存・再利用・Skill

- 「グラフと質問を保存」で JSON をエクスポートし、後で読み込めば質問を続行できます。
- 「対話リプレイのエクスポート」は自己完結型 HTML を生成し、オフラインで開いて共有できます。
- Web エクスポートはローカルの `outputs/exports/` にも書き込まれます。
- CLI は回答前に `graph.json` を保存するため、回答に失敗しても完成したグラフは失われません。

API キーは環境変数 `NOVEL_API_KEY` に設定し、コマンド引数やリポジトリには入れないでください。`NOVEL_API_BASE`、`NOVEL_API_MODEL` で既定値を設定できます。

```bash
python cli.py --novel novel.txt --question "犯人はどうやって現場を去ったか？" --base-url https://your-provider.example/v1 --model YOUR_MODEL --out outputs/my-novel
python cli.py --graph outputs/my-novel/graph.json --question "どの証言が矛盾しているか？" --model YOUR_MODEL --out outputs/question-2
```

ドメイン例はプレースホルダーなので、実際の API に置き換えてください。エンコーディングは `--encoding gb18030` で指定できます。成功時は `graph.json`、`session.json`、`replay.html` が出力されます。

[Releases](https://github.com/fuxiaoji/novel-graph-lab/releases) から `novel-graph-lab-skill.zip` をダウンロードし、`~/.codex/skills/` などのスキルディレクトリに展開してください。`$novel-graph-lab` として呼び出し、`NOVEL_GRAPH_LAB_HOME` でプロジェクトの場所を指定できます。配布パッケージには実行可能なプロジェクトテンプレートが含まれます。

## コスト・プライバシー・限界

既定で各チャンク約 5,000 文字。未キャッシュのチャンクは約 1 回の抽出リクエスト、質問ごとに約 2 回のモデルリクエストが必要で、ネットワークエラーやレート制限により有限回の再試行が発生する場合があります。完了したチャンクのキャッシュは再利用できます。停止は進行中のリクエストが返ってから有効になります。入力ファイルは 20 MB、リクエストは 40 MB が上限です。

API キーはページと現在のジョブのメモリにのみ保持され、キャッシュ・ログ・エクスポートには書き込まれません。タスク実行時、小説のチャンクと質問は設定した API に送信されます。キャッシュとエクスポートされたグラフには小説本文が含まれる可能性があります。サーバーは 127.0.0.1 のみにバインドされ、多人数向けの公開デプロイには適しません。

これは動作する研究プロトタイプです。固定の検索予算、局所的な抽出、曖昧な名前により取りこぼしが起こり得ます。引用が存在しても関係や回答が正しいことを保証しません。自動テストとローカルのモック API で機能フローは検証済みですが、**実モデルでの精度、100 万文字級の性能、他手法に対する優位性は主張していません**。履歴アニメーションは保存済みノードと実際のエッジから再構築し、欠落した計画やログを捏造しません。
